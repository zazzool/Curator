# VPN только для запросов к моделям

Сайдкар с клиентом AmneziaWG и SOCKS5-прокси. Через него ходит **только**
клиент поставщика моделей: раздача задач приложению, студия и база данных
продолжают работать напрямую.

Заворачивать в туннель весь сервер было бы проще, но неправильно: VPN нужен
ради одного адресата, а платили бы за него все — задержкой, лишней точкой
отказа и невозможностью понять, куда именно делся трафик.

## Настройка

1. Возьмите конфигурацию клиента AmneziaWG со своего сервера (в приложении
   Amnezia — «Экспорт конфигурации», формат `awg`). Файл выглядит так:

   ```ini
   [Interface]
   PrivateKey = …
   Address = 10.8.1.2/32
   DNS = 1.1.1.1
   Jc = 4
   Jmin = 40
   Jmax = 70
   S1 = 60
   S2 = 90
   H1 = 1234567890
   H2 = …
   H3 = …
   H4 = …

   [Peer]
   PublicKey = …
   AllowedIPs = 0.0.0.0/0
   Endpoint = ваш-сервер:51820
   PersistentKeepalive = 25
   ```

2. Положите его на контуре рядом с `docker-compose.yml` под именем
   `vpn/awg0.conf` и закройте от посторонних:

   ```bash
   mkdir -p /root/curator/vpn
   install -m 600 awg0.conf /root/curator/vpn/awg0.conf
   ```

   В репозиторий этот файл не попадает никогда — в нём приватный ключ, а
   репозиторий публичный. Каталог `vpn/` закрыт в `.gitignore`.

   Внутрь контейнера он смонтирован только для чтения: служба, способная
   переписать файл с приватным ключом, однажды его перепишет.

3. Поднимите сайдкар — он в отдельном профиле и сам по себе не стартует:

   ```bash
   docker compose --profile vpn up -d llm-vpn
   docker compose logs -f llm-vpn     # ждём «туннель поднят, прокси на 1080»
   ```

4. Убедитесь, что сервер знает адрес прокси. В `/root/curator/.env`:

   ```
   CURATOR_LLM_PROXY=socks5://curator-llm-vpn:1080
   ```

   Это и есть умолчание, так что строка нужна только если её оттуда убрали.
   Адрес — имя контейнера: менять его нельзя, не поправив настройку.

## Что удерживает трафик в туннеле

- **Без туннеля прокси не запускается.** Точка входа ждёт рукопожатия
  30 секунд и, не дождавшись, гасит интерфейс и не поднимает `sockd`.
  Открыть прокси «пока без VPN» значило бы, что запросы молча пойдут
  напрямую, а заметить это будет нечем — ответы-то приходят.
- **Аварийный выключатель.** После подъёма туннеля исходящий трафик
  контейнера разрешён только через `awg0`, в локальную сеть docker и на сам
  адрес VPN-сервера. Отвалится туннель — запросы начнут падать. Это
  правильное поведение: молча уйти в обход VPN хуже, чем не уйти никуда.
- **Потерянное рукопожатие гасит прокси.** Сторожевой цикл раз в десять
  секунд спрашивает у интерфейса время последнего рукопожатия и, не найдя
  его, поднимает туннель заново вместе с прокси.
- **Проверка состояния смотрит на рукопожатие, а не на процесс.** Живой
  процесс здесь ничего не значит: прокси без туннеля — это ровно та
  неисправность, которую нужно поймать.

## Проверить, что трафик действительно идёт через VPN

```bash
# Адрес, с которого сайдкар выходит наружу, должен принадлежать VPN.
docker exec curator-llm-vpn awg show awg0

# А сам сервер — своему провайдеру. Адреса обязаны различаться.
docker exec curator          curl -s https://api.ipify.org; echo
docker exec curator-llm-vpn  curl -s https://api.ipify.org; echo
```

Второй пары команд нет в образах по умолчанию (`curl` не установлен) — это
разовая проверка, ставьте `curl` времянкой или сверяйте адрес на стороне
VPN-сервера.

## Что пришлось учесть

Три вещи, на которых подъём туннеля в контейнере спотыкается:

- **Пустые параметры обфускации.** Приложение Amnezia выгружает все ключи,
  включая незаданные (`I2 = ` без значения), а `awg setconf` на такой строке
  отказывается разбирать файл целиком — исправная конфигурация выглядит как
  негодная. Точка входа отфильтровывает пустые значения в рабочую копию;
  исходный файл она не трогает, он смонтирован только для чтения.
- **`awg-quick` не ставится `make install`.** Это обычный bash-скрипт
  (`src/wg-quick/linux.bash`), и сборка кладёт его сама.
- **`/proc/sys` в контейнере только для чтения**, и `awg-quick` падает на
  `sysctl src_valid_mark`. Значение задаётся декларативно в
  `docker-compose.yml`, поэтому в скрипте эта строка сделана необязательной.

`amneziawg-go` и `amneziawg-tools` собираются из исходников с ветки `master`:
в пакетах Alpine их нет. Если сборка отвалится после обновления апстрима,
зафиксируйте ревизию: `--build-arg AWG_GO_REF=v0.2.12`.

## Чем это отличается от сайдкара-донора

Код и доводы перенесены из MVExams, где всё это куплено отказами. Разошлись
в трёх местах, и каждое — следствие того, что у Куратора нет редактора
настроек VPN:

- **Конфигурацию кладёт человек на контуре, а не студия через общий том.**
  Заводить ради файла, который меняют раз в год, право, экран и том — это
  механизм вокруг действия, которого почти не бывает.
- **`status.json` не пишется.** У донора его читал экран настроек; здесь
  такого экрана нет, и файл состояния, который никто не открывает, — это
  выдумка, расходящаяся с правдой молча. Сообщения идут в журнал контейнера.
- **Потеря рукопожатия поднимает туннель заново.** Донор её только
  записывал в состояние и ждал, что человек посмотрит на экран; смотреть
  здесь некому.
