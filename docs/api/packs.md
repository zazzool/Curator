# Наборы задач: подписанный выпуск и работа без сети

Набор — единица доставки. Врач ставит его целиком и решает задачи, когда
сети нет: в метро, в отделении, в дороге. Лента этого не даёт — она
страница за страницей, и вторая страница в метро не приедет.

## Почему выпуск подписан

Между устройством и сервером стоит чужая сеть. Подменить содержание по
дороге может всякий, кто в ней сидит, и заметить подмену можно только
подписью. Приложение сверяет её **до** установки.

Подпись — ed25519 по описи выпуска. Закрытая половина ключа живёт в
окружении (`PACK_SIGNING_KEY`) и в базу не попадает никогда: утёкшая база не
должна давать права подписывать.

**Открытого ключа сервер не отдаёт.** Выпуск несёт имя ключа (`keyId`), но
не сам ключ. Отдай мы ключ той же дверью, что и набор, подпись перестала бы
значить что-либо: подменивший набор по дороге подменил бы и ключ. Ключи,
которым верит приложение, приезжают в его сборке; `keyId` нужен лишь затем,
чтобы выбрать верный из них при смене ключа.

## Как считаются подписываемые байты

Правило записано в `shared/pack-manifest.json` вместе с разобранным
примером — его читают обе стороны. Разойдись два способа привести опись к
байтам, и подпись не сойдётся ни на одном устройстве.

1. Ключи объектов — по алфавиту, на всех уровнях.
2. Никаких пробелов и переводов строк.
3. UTF-8 как есть; `<`, `>` и `&` **не** экранируются.
4. Время — RFC 3339 в UTC.
5. Задачи в порядке поля `ord`.

Два пункта тут стоят объяснения.

**Подписывается не то, что лежит в базе.** Опись хранится колонкой JSONB, а
JSONB не хранит ни порядок ключей, ни пробелы: postgres пересобирает объект
по-своему. Подпиши мы вынутое из базы — подпись не сошлась бы нигде, а
глазами оба текста одинаковы, и причину искали бы неделю.

**Экранирование выключено явно.** Библиотека Go по умолчанию превращает
`<`, `>` и `&` в `<`, `>`, `&` — это наследство встраивания
JSON в HTML, и больше никто так не делает. Набор с амперсандом в названии
подписался бы у нас одними байтами, а на устройстве свернулся бы в другие, и
подпись не сошлась бы ровно у того выпуска, у которого в названии стоит
«и».

## Выпуск неизменяем

Правка набора — это **новый выпуск**, а не правка старого. На устройствах
стоит именно тот состав, который подписан, и подменить его задним числом
значит сделать подпись бессмысленной.

Состав при этом правится свободно: выпуск — снимок состава на миг подписи, и
новый состав доедет до устройств только следующим выпуском.

В выпуск попадают **только опубликованные** задачи. Черновик, уехавший в
набор, — это задача, которую никто не принимал, показанная врачу с нашей
подписью. Снятая с раздачи задача в новый выпуск не попадает, а в прежних
остаётся: выпуск неизменяем.

Пустой набор не выпускается вовсе: подписанный пустой набор установится на
устройство и покажет врачу пустой экран, причём с нашей подписью.

## Витрина

```bash
curl -s "$СЕРВЕР/v1/packs" -H "Authorization: Bearer $ТОКЕН"
```

```json
{"packs": [{"slug": "cardio-basics", "title": "Кардиология: начало",
            "summaryMd": "...", "version": 3, "cases": 120}]}
```

Показываются только наборы с выпуском: набор, который нельзя скачать, в
витрине — обещание, а не товар.

## Опись выпуска

```bash
curl -s "$СЕРВЕР/v1/packs/cardio-basics" -H "Authorization: Bearer $ТОКЕН"
```

```json
{"slug": "cardio-basics", "version": 3, "title": "Кардиология: начало",
 "releasedAt": "2026-09-19T10:00:00Z",
 "signature": "…", "keyId": "key-1",
 "cases": [{"id": "c-nx4k2p7q9wvz3mrt", "ord": 0, "hash": "sha256:…"}]}
```

**Отпечаток у каждой задачи, а не один на весь набор.** Устройство качает
задачи по одной и обязано проверить каждую: проверка «весь набор целиком» на
обрыве посреди закачки не говорит ничего.

## Скачивание

```bash
curl -s "$СЕРВЕР/v1/packs/cardio-basics/cases?limit=100&after=c-nx4k2p7q9wvz3mrt" \
     -H "Authorization: Bearer $ТОКЕН"
```

Страницей, а не целиком: набор на тысячу задач весит мегабайты, и телефон в
метро не дотянет одну большую закачку. `next` пуст, когда страниц больше
нет; оборвавшаяся закачка продолжается с курсора, а не начинается заново.

## Со стороны студии

| Ручка | Что делает |
|---|---|
| `POST /admin/api/packs` | завести набор |
| `PUT /admin/api/packs/{slug}/items` | задать состав целиком |
| `POST /admin/api/packs/{slug}/releases` | собрать и подписать выпуск |
| `GET /admin/api/packs` | список наборов |

Все закрыты правом `packs`. Выпуск — отдельное действие, потому что
выпустить значит подписать нашим ключом то, что встанет на устройства и
переживёт любую правку.

**Состав задаётся целиком, а не по одной задаче.** Состав — это порядок, и
правка по одной превращает его в череду мелких решений, из которых порядок
не виден никому. Заодно снимается вопрос, что делать с убранной задачей: её
просто нет в присланном списке.

## Право на скачивание

Набор с действующей ценой отдаёт содержание только тому, кто его купил или
держит подписку; набор без цены открыт всем. Опись при этом открыта
всегда — по номерам и отпечаткам не позанимаешься. Разобрано отдельно:
[доступ и продажи](sales.md).
