# Редакционное API: задачи

Третий этап сквозного пути начинается здесь. Вход тот же, что у источников
([sources.md](sources.md)).

```bash
СТУДИЯ=http://127.0.0.1:8080
```

## Права

| Право | Что открывает |
|---|---|
| `case:read` | читать задачи и версию содержания |
| `case:write` | заводить, править, выпускать в раздачу и снимать |

Выпуск и снятие закрыты одним правом, а не разными: это одно решение,
принятое в две стороны, и развести их значило бы разрешить одному
выпускать, а другому снимать.

## Черновик становится задачей

Черновик, написанный конвейером, задачей ещё не является: у него нет ни
номера, под которым его узнает устройство, ни разрешённых ссылок на
положения, ни места в источнике.

```bash
curl -s -X POST "$СТУДИЯ/admin/api/cases" \
  -H "Authorization: Bearer $ТОКЕН" -H 'Content-Type: application/json' \
  -d '{"draftId":12}'
```

Черновик при этом остаётся на месте: он — след того, что ответила модель,
и нужен, когда задача вышла плохой, а понять почему уже не по чему.

Источник и метка единицы берутся у черновика, а не у того, кто заводит:
черновик написан по конкретной единице, и подменить её при заведении
значило бы получить задачу, проверяющую не то, что написано.

**Путь единицы копируется в задачу при заведении** и больше не меняется.
Подбор задач по срезу пути обязан работать одним запросом, без соединения
с деревом источника; переписанный путь у старой задачи означал бы
молчаливую смену её места в подборе — задача уехала бы в другой раздел, и
никто бы этого не заметил.

Номер задачи не порядковый и не производный от источника. Порядковый
называет вслух, сколько задач написано; производный от метки ломается на
втором источнике с той же нумерацией пунктов — ровно та беда, от которой
уходит вся эта модель.

## Список и срез

```bash
curl -s "$СТУДИЯ/admin/api/cases?source=1&path=3&status=published" \
  -H "Authorization: Bearer $ТОКЕН"
```

`path` — срез по пути: «всё, что под 3» это 3, 3.1, 3.2 и всё, что ниже.
Считается по данным источника, а не по форме метки.

Состояния: `draft` черновик, `review` на выверке, `published` раздаётся,
`archived` снята с раздачи. Каждое уезжает и меткой (`status`), и словом
(`statusWord`): сортирует студия по метке, а читает человек слово.

## Правка

```bash
curl -s -X PUT "$СТУДИЯ/admin/api/cases/c-abcdefgh23456789" \
  -H "Authorization: Bearer $ТОКЕН" -H 'Content-Type: application/json' \
  -d '{"revision":3,"body":{ … }}'
```

Редакция сверяется условием самого `UPDATE`. Не та — `409`. Прежний текст
уезжает в `case_revisions`: неудачную редактуру врачебного текста надо
уметь вернуть, а не переписывать по памяти.

**Раздаваемая задача не правится.** Правка молча меняет то, что уже видят
на устройствах, и расходится с попытками, записанными по прежнему тексту.
Снять с раздачи — отдельное решение, и принимается оно отдельно.

## Выпуск в раздачу

```bash
curl -s -X POST "$СТУДИЯ/admin/api/cases/c-abcdefgh23456789/publish" \
  -H "Authorization: Bearer $ТОКЕН"
```

Отказ приходит **списком замечаний разом**, а не первым из них:

```json
{"error":"Задачу пока нельзя раздавать — вот что мешает",
 "faults":[{"where":"разбор","what":"пустой: обучающийся увидит вердикт без обоснования"},
           {"where":"ответ","what":"не совпадает ни с одним вариантом — зачесть ответ будет нечем"}]}
```

Составитель правит задачу в один заход, и отказ, называющий одну беду из
четырёх, заставляет его ходить по кругу ровно четыре раза.

Что мешает раздавать: пустое название, пустое условие, меньше двух
вариантов, ответ, не совпадающий ни с одним вариантом, пустой разбор, не
указанная единица источника, ссылка на несуществующее положение, метка
единицы в тексте условия.

Повторная публикация не отказывает: составитель нажал дважды, и он хотел
раздачи.

## Разметка раскладывается при выпуске

Обозначение положения («абз. 1») осмысленно всегда; номер положения в базе
— только пока положение живо. Поэтому разметка хранится в задаче
обозначениями, а по номерам раскладывается **при выпуске**, в ту же
транзакцию, что и смена состояния. Разложить её заранее значит получить
ссылку в никуда у задачи, лежавшей в черновиках месяц.

Фрагмент, подтверждающий два положения, занимает две строки разметки: она
хранится по фрагменту, а не по паре.

## Снятие с раздачи

```bash
curl -s -X POST "$СТУДИЯ/admin/api/cases/c-abcdefgh23456789/withdraw" \
  -H "Authorization: Bearer $ТОКЕН"
```

Строка задачи **не удаляется никогда**. На устройствах задача уже стоит,
попытки по ней уже записаны, и задача, исчезнувшая из базы, оставила бы
попытки, ссылающиеся в никуда, — то есть испортила бы отчёты задним
числом.

## Версия содержания

```bash
curl -s "$СТУДИЯ/admin/api/content-version" -H "Authorization: Bearer $ТОКЕН"
```

Приложение сравнивает её со своей и качает только при расхождении. Версия
растёт и на выпуске, и на снятии: устройство, не узнавшее о снятии,
продолжит показывать задачу, которую составитель уже счёл негодной.
