# Выкатка

Контур — `curator.psync.ru`. Выкатывает `./deploy.sh`: исходники едут на
хост, образ собирается там. Реестра образов у проекта нет, а собирать на
машине разработчика нечем — Docker стоит не везде.

**Зовёт его сторож, а не человек.** Всякое зелёное слияние в `main`
уезжает на контур само — `.github/workflows/deploy.yml`. С машины
разработчика тот же скрипт запускается руками и работает по-прежнему;
это путь для случая, когда GitHub недоступен, а выкатить надо.

## Автоматическая выкатка

**Заводится один раз** с машины, у которой уже есть доступ к контуру:

```bash
./deploy/setup-auto-deploy.sh
```

Скрипт порождает ключ, кладёт открытую половину на контур, снимает
отпечаток хоста, проверяет ключ делом и кладёт в секреты репозитория
`CURATOR_SSH_KEY` и `CURATOR_SSH_KNOWN_HOSTS`. Закрытая половина не
показывается на экране и не остаётся на машине: каталог с ней стирается
при выходе. В репозиторий она не попадает никогда — он публичный.

**Дальше сторож выкатывает сам.** Порядок такой:

1. Слияние в `main` будит проверки (`checks.yml`).
2. Проверки зелены — просыпается выкатка и берёт **тот коммит, на котором
   сторож сказал «зелено»**, а не голову ветки: пока шли проверки, в неё
   мог влиться следующий, и выкатилось бы непроверенное.
3. Дальше — обычный `./deploy.sh`: опрос базы, копирование, сборка, накат
   схемы, подмена контейнера, ожидание `/healthz`.

Проверки красны — выкатки не происходит вовсе.

**Руками — вкладка Actions → «Выкатка» → Run workflow.** Там два дела:
выкатить повторно и вернуть предыдущий образ. Возврат оттуда — это тот
же `./deploy.sh --rollback`, и нужен он, когда машины владельца рядом
нет, а контур уже горит.

Ручная выкатка **тоже спрашивает сторожа**: кнопка, выкатывающая красное,
была бы дверью мимо него, а ради такой двери сторожа и заводят. Обойти её
можно вслух — входом `force`, и нужен он ровно в одном случае: когда
чинится сам сторож.

**Ключ даёт root на контуре.** Поэтому он живёт только в секретах
репозитория, куда правом записи не обладает никто, кроме владельца, и
только оттуда попадает на раннер — файлом, а не переменной окружения:
переменная утекла бы в журнал первой же командой, печатающей окружение.
Отпечаток хоста заводится отдельным секретом и проверяется:
`StrictHostKeyChecking=no` здесь отдал бы контур первому, кто сумеет
ответить вместо него.

Отозвать доступ:

```bash
ssh root@curator.psync.ru "sed -i '/curator-deploy (GitHub Actions)/d' ~/.ssh/authorized_keys"
```

**Если на контуре ssh закрыт для чужих адресов**, ключа мало: адреса
раннеров GitHub меняются и занимают целые сети, и открывать порт 22 им
всем — плохой размен. Тогда выкатку берёт на себя **свой раннер на самом
контуре** (`runs-on: self-hosted` вместо `ubuntu-latest`): ssh тогда идёт
с контура на самого себя и наружу не выходит вовсе. Это единственное,
что придётся изменить в файле выкатки.

## Порядок и почему он такой

1. Статические проверки этой машины (`gofmt`, `go vet`, `npm run
   typecheck`). Секунды, а ловят неотправляемое.
2. Опрос базы на контуре (`deploy/preflight.sql`). По ответу видно, та ли
   это база: сколько таблиц, сколько источников и задач, кто заведён в
   студии. Ничего не меняется.
3. Копирование исходников и сборка образа. Перед сборкой на работающий
   образ ставится метка `previous` — после сборки было бы поздно, и
   возврат вернул бы то же, что сломало контур.
4. **Накат схемы — до подмены кода.** Код, вышедший раньше своей схемы,
   падает не при старте, а на первом обращении к недостающей колонке: то
   есть у врача, а не в журнале выкатки. Схема растёт только добавлением,
   поэтому старый код на новой схеме работает по-прежнему, а обратное
   неверно.
5. Подмена контейнера и ожидание `/healthz` снаружи.

Не ответил — `./deploy.sh --rollback`. Возврат идёт первым делом, без
проверок: он нужен тогда, когда контур уже горит.

## Что нужно на контуре один раз

**Сеть nginx.** Контейнер наружу не смотрит: TLS и заголовки — на общем
`nginx-proxy` хоста, он же обращается к службе по имени контейнера.
Поэтому имя `curator` и есть адрес службы, и менять его нельзя, не
поправив конфигурацию прокси.

**Файл `.env` в каталоге выкатки** (`/root/curator/.env` по умолчанию).
Его читает `docker compose`, и выкатка его не трогает: там боевые
секреты, и живут они отдельно от репозитория. Образец со всеми
переменными и доводами — `server/.env.example`. В разработке тот же файл
лежит в `server/.env`, и читает его сам сервер; на контуре переменные
задаёт docker, и файла в образе нет.

**Ключ подписи наборов.** Без него служба поднимается и раздаёт уже
выпущенное, а выпуск нового отказывает — словами, а не молчанием. Пара
порождается утилитой, а не руками: `openssl` отдаёт ed25519 в обёртке
PKCS#8, а сервер ждёт голые 64 байта в base64, и переписанная с ошибкой
строка выдаёт себя только на первом выпуске.

```bash
cd server && go run ./cmd/packkey -id key-1
```

Закрытая половина уезжает в `.env` контура, открытая — в сборку
приложения (`--dart-define=CURATOR_PACK_KEYS=…`), и обратно её оттуда не
достать. Ключ донора сюда не переносится: сборки Куратора подписаны
своим, и общий ключ связал бы два продукта там, где связь не нужна
никому.

**Первый пользователь студии.** Пользователей заводит мастерская, а
заводит их пользователь с правом `workshop`. На свежем контуре такого нет
ни одного, и войти, чтобы завести первого, нельзя по кругу. Разрывает
круг утилита из того же образа:

```bash
docker compose run --rm --no-deps --entrypoint /app/user curator \
    -login editor -name Составитель -perms all
```

Она печатает секрет и ссылку привязки **один раз**: секрет хранится,
чтобы сверять коды, а показанный второй раз он превращается во второй
пароль, лежащий рядом с первым. Потерян — пользователь заводится заново.

Кто уже заведён, показывает та же утилита с `-list`. Дальше пользователи
заводятся и правятся в самой мастерской, и разрывать круг второй раз не
придётся: снять право `workshop` с последнего, у кого оно есть, студия
не даёт — иначе заводить стало бы некому и некем, и лечилось бы это
снова руками на контуре.

**Справочник на устройствах.** Свежий контур поднимается без единого
источника, и раздел «Справочник» в приложении на нём пуст. Каталог
ввозится тем же образом из файла выгрузки, лежащего рядом:

```bash
docker compose run --rm --no-deps -v /root/curator/import:/import:ro \
    --entrypoint /app/importcatalog curator \
    -catalog /import/icd10_catalog_v1.json -source icd10 \
    -title 'МКБ-10: психические расстройства и расстройства поведения' \
    -unit-word рубрика -statement-word критерий \
    -edition 'версия 2019, CDDG 1992 и DCR-10 1993' \
    -apply -activate
```

Без `-apply` она ничего не пишет и печатает те же числа, что записала бы;
замер на настоящей выгрузке — 954 единицы и 765 положений. Без
`-activate` источник остаётся черновиком и на устройства не едет вовсе:
`/v1/reference` отдаёт только действующие. Объявить его действующим можно
и потом, из студии.

Файл выгрузки в репозитории не лежит и лежать не будет: он несёт текст,
права на который принадлежат не нам, а репозиторий открытый. Подробности
ввоза — `docs/import.md`.

**Прокси к поставщику моделей.** Обращения к моделям идут через сайдкар
с VPN — и только они: раздача задач, студия и база работают напрямую.
Сайдкар живёт в отдельном профиле и вместе с сервером не поднимается,
потому что без конфигурации туннеля ему нечего делать:

```bash
mkdir -p /root/curator/vpn
install -m 600 awg0.conf /root/curator/vpn/awg0.conf
docker compose --profile vpn up -d llm-vpn
```

Конфигурация с приватным ключом в репозиторий не попадает никогда и
внутрь контейнера смонтирована только для чтения. Откуда её взять, чем
прокси держит трафик в туннеле и как убедиться, что он там, —
`deploy/llm-vpn/README.md`.

Сайдкар не поднят — обращения к моделям пойдут напрямую (или не пойдут
вовсе, если поставщик закрыт), а всё остальное работает целиком:
источники, раздача задач, продажи, отчёты. Отказа при старте нет
намеренно.

## Чего эта выкатка пока не приносит

**Снимки базы.** Каталог под них заводится и права на нём выставляются
(`backups`, uid 10001), но снимает их пока никто: `CURATOR_BACKUP_DIR` в
коде не читается. Пока это так, задачи существуют в одном экземпляре.

**Выкладка приложения.** Сборка Android выкладывается отдельно и в эту
выкатку не входит.
